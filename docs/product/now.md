## Recently done

- **Worktree bootstrap race fix** (2026-05-13, [PR #52](https://github.com/mdml/gc-erp-mcp-server/pull/52), commit [c54e6bf](https://github.com/mdml/gc-erp-mcp-server/commit/c54e6bf)): in a fresh Zed-opened worktree with Claude attached, the `create_worktree` task and `SessionStart` hook were both running `bun install` and racing on `clonefileat`, leaving a half-linked `node_modules` (only top-level binaries materialized). Fix funnels both launchers through `just bootstrap`, which wraps `bun install` in an mkdir-lock so concurrent fires serialize instead of racing. Inline-per-launch-path design from 4218617 preserved (no shared script regrows); the lock is the only common layer. First time the Zed-with-Claude worktree scenario works end-to-end without manual recovery. Closes out the post-Slice-A flake-chasing run (#43–#47 were chasing the wrong cause; #52 named the actual concurrency).
